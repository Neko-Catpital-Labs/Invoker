## Finding 1: Guard normal shutdown after signal-owned shutdown begins

Quoted finding:

> Guard the normal quit cleanup when the signal handler already owns shutdown.
>
> For `owner-serve`, `runHeadless(cliArgs, headlessDeps)` blocks while `headlessOwnerServe` polls, so a SIGTERM/SIGINT can start signal cleanup asynchronously. The `finally` block then enters `runHeadlessShutdownCleanup` regardless, so it can call `persistence.requeueRunningWorkflowMutationIntents()`, `persistence.close()`, `writerLock.release()`, and `messageBus.disconnect()` a second time. Guard the final cleanup and `process.exit(exitCode)` so only the first shutdown path runs cleanup.

Severity: Major

Verdict: invalid

Evidence:

The double-cleanup path described by CodeRabbit is fixed on current `origin/master`. `packages/app/src/main.ts:933` makes `owner-serve` part of standalone mode, and `packages/app/src/main.ts:934` scopes `ownsHeadlessShutdown` specifically to non-read-only `owner-serve`. The signal handler only registers under that ownership condition, and `packages/app/src/main.ts:1068` returns immediately if `headlessSignalShutdownInProgress` is already set. On first SIGTERM/SIGINT, `packages/app/src/main.ts:1069` sets `headlessSignalShutdownInProgress = true` before calling `runHeadlessShutdownCleanup` at `packages/app/src/main.ts:1071`.

The normal `runHeadless` cleanup path is guarded by the same flag. In the `finally` block, `packages/app/src/main.ts:2037` checks `if (!headlessSignalShutdownInProgress)`, `packages/app/src/main.ts:2038` sets the flag before normal cleanup, `packages/app/src/main.ts:2039` runs `runHeadlessShutdownCleanup('Application quit')`, and `packages/app/src/main.ts:2040` exits with the normal exit code. If signal shutdown has already started, this block is skipped, so the normal path cannot call `persistence.requeueRunningWorkflowMutationIntents()`, `persistence.close()`, `writerLock.release()`, or `messageBus.disconnect()` a second time.

Regression coverage exists on current `origin/master`: `packages/app/src/__tests__/headless-termination-signal-handling.test.ts:57` names the behavior as skipping normal-quit cleanup and exit when the signal handler already owns shutdown, and `packages/app/src/__tests__/headless-termination-signal-handling.test.ts:62` through `packages/app/src/__tests__/headless-termination-signal-handling.test.ts:63` assert the `if (!headlessSignalShutdownInProgress)` guard and the flag set before normal cleanup.
